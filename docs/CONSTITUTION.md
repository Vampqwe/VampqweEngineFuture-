# ⚖️ Конституция и Теорема синхронизации

Документ фиксирует **исполняемое** соответствие между десятью принципами
Конституции (таблица в `README.md`) и машинными проверками. Формулировка
теоремы продублирована в PHPDoc класса `App\Core\System\Support\ArchitectureLinter`
(«доказательство строится построчно») — здесь реестр, в коде доказательства.

## 📜 Т е о р е м а  о синхронизации

> Если `php bin/engine lint-rules` завершается с кодом 0 **и**
> `php bin/engine test` завершается с кодом 0, то код проекта соответствует
> Конституции (п.1–п.10) и правилам стиля README.

Королларий: любое нарушение Конституции обязано проявиться красным CI — либо
статическим детектором (R1–R11), либо падающим тестом. Если нарушение не
проявляется — это баг теоремы (слепое пятно), он закрывается новым правилом
или тестом, а не аннотацией.

## 🔗 Карта доказательств: правило → чем проверяется

| Пункт | Формулировка (кратко) | Статика (lint-rules) | Тесты |
|-------|------------------------|----------------------|-------|
| п.1 | Ядро не знает бизнес-логику и конкретные классы модулей | R6 (ссылки core/System на классы модулей вне белого списка контрактов), R6b (единственный носитель знания о `::class` модулей — `Support/ModuleBridge.php`), R8 (аннотированные исключения) | `KernelBoundaryTest::testKernelSurvivesWithoutApplicationModules` (T1), `testOnlyModuleBridgeKnowsModuleClassNames` (T4a) |
| п.2 | Граница модуля — только `Contracts/`, `Internal/` закрыт | R3 (трансграничные use Internal\), R9 (new/instanceof через границы), R10 (крипто ровно в одном месте), R11b (scalar-константы контрактов доступны без нарушения п.2) | `SecurityTest` (roundtrip единого Crypto), юнит-тесты модулей через контракты |
| п.3 | DI, никаких глобалов и service locator | R2 (dirname-пути), R7 (BASE_PATH только в bootstrap путей), R11c (нет static-состояния в контрактах) | `ContainerTest` (autowiring, циклы, instance) |

Правила линтера без прямой привязки к пункту (чистый стиль): R11a — контракты
без default-значений параметров (реализация обязана объявлять значения сама).

## 🚪 Задокументированные исключения (белые списки линтера)

Исключение легально **только** при одновременном выполнении:
1. файл записан в белый список `ArchitectureLinter` (`EXCEPTION_WHITELIST` /
   `TEST_INTERNAL_WHITELIST` / `CORE_ALLOWED_REFERENCES`);
2. в файле есть аннотация `@constitution-exception п.N: <обоснование>` —
   иначе R8 ловит запись whitelist как устаревшую лазейку.

| Файл | Пункт | Обоснование |
|------|-------|-------------|
| `core/System/Support/FatalPage.php` | п.2 | Аварийная страница последнего средства: рисуется до/вне контейнера, когда модуль Error может быть недоступен (п.10 приоритетнее чистоты границы). |
| `core/System/Support/SuperAdmin.php` | п.2 | Фиксированный root движка: константа ядра, не БД и не модуль — иначе «кто создаёт первого админа» становится курицей и яйцом. |
| `core/System/App.php`, `core/System/Support/Paths.php` | п.7 | Физический bootstrap путей: единственные места ядра, читающие `BASE_PATH` (define — в `public/index.php`/`bin/engine`, они вне TARGETS). |
| `tests/Unit/SecurityTest.php` | п.2 | Юнит-тест внутренней криптографии обязан иметь доступ к объекту теста (`Internal/Crypto`). |
| `tests/Unit/KernelBoundaryTest.php` | п.7 | Инспекция исходников: читает `core/System/**` как данные, корень репозитория находит бытовым `dirname(__DIR__, 2)`; путями приложения не оперирует. |

## 🧾 Долг, вынесенный за теорему

* Нет автоматического детектора «перегруженного метода» (эвристики SRP
  субъективны) — объём `Kernel.handle()` контролируется ревью, поведение
  закреплено тестами T1–T4.

~~Doctor-проверка `.env`-секретов на утечку в репозиторий~~ — **закрыто**:
детектор живёт в `core/Module/Doctor/Checks/SecretLeakCheck.php` и встроен в
pipeline Doctor'а; покрыт стендовыми юнит-тестами
`tests/Unit/SecretLeakCheckTest.php` (6 сценариев: вне git — честный пропуск;
чистый стенд; .env без ignore-правила; закоммиченный .env (`git add -f`);
значение секрета в отслеживаемом файле; короткие заглушки не считаются).
Таким образом п.8 («секреты не попадают в репозиторий») перешёл из декларации
в исполняемую проверку теоремы: красный doctor ⇒ красное CI.

Всё, что не имеет детектора или теста, помечено здесь как debt и **не
участвует в теореме**; перевод пункта в теорему = новый R-правило или тест.

## ▶️ Исполнение (merge-gate)

CI (`.github/workflows/ci.yml`) запускает обе части теоремы на PHP 8.1/8.3:

```bash
composer dump-autoload
php bin/engine lint-rules   # статика: R1–R11
php bin/engine test         # поведение: все Unit-тесты
php bin/engine doctor       # smoke: честная самодиагностика живого дерева
```

Для детерминизма doctor в CI собирается sqlite-стенд из `.env.example`
(`DB_DRIVER=sqlite`, `DB_SQLITE_ENABLED=true`, `DB_DATABASE_PATH=engine.sqlite`) —
без реальных СУБД и секретов; локально достаточно `cp .env.example .env` и тех же
трёх замен (или установки через `/install`).

Любой ненулевой exit code блокирует merge. Таким образом, «зелёный CI ⇒
соответствие Конституции» — свойство репозитория, а не надежда ревьюера.
